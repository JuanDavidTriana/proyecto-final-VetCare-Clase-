# ADR-0002 · Autenticación con JWT stateless

- **Estado:** Aceptada
- **Fecha:** Sprint 0

## Contexto

La SPA de Angular y la API se despliegan por separado (posiblemente en dominios distintos). Necesitamos autenticar las peticiones y saber el rol del usuario en cada una.

## Decisión

- Al iniciar sesión, la API firma un **JWT** con el payload `{ id, role }` y una expiración de `8h`.
- El frontend lo envía en la cabecera `Authorization: Bearer <token>` mediante un interceptor.
- La API lo verifica en el middleware `authenticate` y autoriza con `authorize(...roles)`.
- Las contraseñas se guardan con **bcrypt** (10 rondas).

## Consecuencias

- ✅ Sin sesiones en el servidor: escala horizontalmente sin estado compartido.
- ✅ El rol viaja en el token y no hace falta consultar la base de datos en cada petición.
- ⚠️ Un token no se puede revocar antes de que expire. Si un usuario se desactiva, puede seguir usando su token hasta 8 horas. Lo mitigamos con una expiración corta, y como mejora futura se puede agregar un refresh token o verificar `active` en las rutas sensibles.
- ⚠️ Guardar el token en `localStorage` lo expone a XSS. Lo mitigamos con el escapado de Angular y CSP vía helmet. La alternativa (cookie httpOnly) se discute en la clase de seguridad.
